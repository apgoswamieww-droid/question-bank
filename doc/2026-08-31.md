## What Was Done

### 1. KAP Font Extensibility Refactor

Goal: single source of truth for the font list, auto-detected everywhere else.

#### TypeScript core
| File | Change |
|------|--------|
| `src/converter/types.ts` | `KapFont` type now **derived** from `KAP_FONTS` constant (`(typeof KAP_FONTS)[number]`) — one place to add a font |
| `src/converter/mappings/index.ts` | `REGISTRY` built from `KAP_FONTS.map()` + new `FONT_DATA` table; `__resetMappingsForTests` now loops over `KAP_FONTS` instead of a hardcoded defaults copy |

#### TypeScript scripts (auto-detect from `mapping-data/glyph-dataset/`)
| File | Change |
|------|--------|
| `scripts/export-verified-mappings.mts` | New `detectFonts()` scans glyph-dataset directories matching `/^KAP\d+$/` |
| `scripts/batch-analyze.mts` | Same `detectFonts()` auto-detection |
| `scripts/generate-analysis-report.mts` | Same `detectFonts()` auto-detection |

#### Python scripts (auto-detect from `public/fonts/kap*.ttf`)
| File | Change |
|------|--------|
| `scripts/generate-glyph-dataset.py` | `KAP_FONTS` dict built from `FONTS_DIR.glob("kap*.ttf")` |
| `scripts/analyze-kap-fonts.py` | Same glob-based detection |
| `scripts/generate-kap-proof-sheets.py` | Same glob-based detection |

**Result**: adding a new font now requires only:
1. Drop `public/fonts/kapNNN.ttf` (Python scripts pick it up automatically)
2. Add `"KAPNNN"` to `KAP_FONTS` in `src/converter/types.ts`
3. Create `src/converter/mappings/kapNNN.ts` + register it in `FONT_DATA` (with import)

### 3. Super Admin Panel (NEW — main feature)

Web-first admin panel with **Super Admin** login, designed for future **Teacher / Student / Parent** roles. Uses Tailwind CSS + React Router. BrowserRouter chosen (Electron will be removed in favor of web in the future).

#### Architecture
```
Browser → /admin → AdminRoutes (AdminAuthProvider)
                ├─ /admin            → Login page (public)
                ├─ /admin/dashboard  → Protected → Dashboard
                └─ /admin/*          → Login page fallback
Browser → /     → existing Question Bank editor (unchanged)
```

#### Dependencies added
| Package | Purpose |
|---------|---------|
| `tailwindcss` + `@tailwindcss/vite` | Tailwind CSS v4 styling |
| `react-router-dom` v7 | BrowserRouter routing |
| `express` v5 | Admin API backend |
| `cors` | CORS for API |
| `bcryptjs` | Password hashing (cost 12) |
| `jsonwebtoken` | JWT auth (issuer, 8h expiry) |

#### Backend (`server/`)
| File | Purpose |
|------|---------|
| `server/index.js` | Express app — CORS, JSON body limit 1mb, `x-powered-by` disabled, health/auth routes, 404 + error handlers |
| `server/config.js` | Reads `.env` (tiny built-in loader), exposes `port`, `jwt`, `superAdmin` config |
| `server/auth.js` | User store load, credential lookup, bcrypt verify, JWT sign/verify, `publicUser` shape (never exposes `passwordHash`) |
| `server/seed.js` | Seeds `server/data/users.json` with one super admin; **generates a random password** if none set; does not overwrite existing store |
| `server/.env.example` | Template for `PORT`, `JWT_SECRET`, `JWT_EXPIRES_IN`, super admin identity |

| Endpoint | Auth | Behavior |
|----------|------|----------|
| `GET /api/health` | none | Liveness probe |
| `POST /api/auth/login` | none | Validates username/email + password → `{ token, user }`; **in-memory per-IP rate limit (10/min)**; constant-time-ish compare via dummy hash on unknown user |
| `GET /api/auth/me` | Bearer JWT | Session restore → `{ user }`; 401 if token invalid/expired or user gone |

Security details:
- `JWT_SECRET` defaults to a dev-only value — must be overridden in production
- Passwords stored as bcrypt hashes; plaintext never logged; random password printed once on seed
- `server/data/users.json` added to `.gitignore`
- Login failure returns generic message; no user enumeration via timing (dummy hash)

#### Frontend admin (`src/`)
| File | Purpose |
|------|---------|
| `src/main.tsx` | Wraps app in `<BrowserRouter>`; routes `/admin/*` → AdminRoutes, `*` → App |
| `src/admin/AdminRoutes.tsx` | Provider-scoped routes (relative paths under `/admin`) |
| `src/admin/AdminLoginPage.tsx` | Responsive dark login card — ambient glows, show/hide password, inline validation, animated error banner, loading state, `noindex`, autofill-safe styling, `min-h-dvh` mobile layout |
| `src/admin/AdminDashboardPage.tsx` | Mobile drawer + desktop sidebar (when `lg`), stat cards (Teachers/Students/Parents/Question Banks), role badge, logout |
| `src/admin/ProtectedRoute.tsx` | Bootstrapping spinner → redirects to `/admin` if no user; renders `<Outlet/>` for protected children |
| `src/context/AdminAuthContext.tsx` | `AdminAuthProvider` — session restore via `/auth/me`, login/logout |
| `src/context/useAdminAuth.ts` | `useAdminAuth()` hook + context (split for fast-refresh lint rule) |
| `src/api/client.ts` | Fetch wrapper — typed `request<T>`, `ApiError` with code/status/retryAfter, automatic 401 session clear, storage abstraction |

Session persistence:
- **Remember me checked** → token in `localStorage` (survives restart)
- **Unchecked** → token in `sessionStorage` (tab-session only)
- Both cleared on logout / 401

### 4.2 Database Schema Highlights

**Questions table** columns:
- `standard_id`, `subject_id`, `chapter_id`, `topic_id` (hierarchy FKs)
- `type` (10 types: mcq_single, mcq_multi, true_false, fill_blank, short_answer, long_answer, match, ordering, image_based, numeric)
- `exam_type_id`, `language_id`, `level_id` (master data FKs)
- `exam_year` (int — year question was used/designed for)
- `content` (Tiptap JSON), `explanation` (solution JSON)
- `marks`, `negative_marks`, `time_limit_sec`
- `quality_score` (auto-calculated 0-100)
- `tags[]`, `status` (draft/published/archived)

**History tables**:
- `question_usage_log` — every time a question appears in a test
- `question_edit_history` — every field change with old/new values
- `question_performance` — aggregated student stats (correct/incorrect/skip rates, avg time)
- `question_teacher_usage` — per-teacher usage aggregation
- `question_school_usage` — per-school usage aggregation

### 4.3 Auto-Update Triggers
- `update_bank_question_count()` — auto-updates `question_count` and `total_marks` on question_banks
- `update_question_performance()` — auto-recalculates success_rate, difficulty_rating on each student answer
- `update_question_quality_score()` — auto-calculates quality score based on usage + performance + recency + freshness
